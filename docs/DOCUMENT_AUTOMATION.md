# Daily document automation · 12 October 2026

The user requested original, useful templates focused on saving Lekhpal time, instead of supplying samples for exact template copying. This implements that scope; it is not a claim that these drafts are government-prescribed formats.

## Where it appears

Dashboard or Services → **Document automation**, in every enabled state. Services search finds documents, applications, orders, inspection and demarcation. Existing UP government screens and Khasra Custom Tab routing are preserved.

## Implemented

- Six editable Hindi/English workflows: general application, record correction request, demarcation request, field inspection report, office order draft and forwarding letter.
- Three-step phone editor: office, person/plot and content. Automatic introductory text, date, structured details, enclosure list and signature space. All output is escaped and locally generated without remote assets.
- Up to 20 named office/village profiles; only office, location and preparer/signatory fields carry over. An applicant signs an application; a profile's preparer is labelled separately.
- Incomplete saved drafts, duplicate-as-new, and search by name, plot, village, date or document. Duplicate-as-new refreshes the date and clears reference, inspection and due dates.
- Paste 1–50 rows (`Name | Parent/spouse | Address | Plot | Khata`), validate every row, review each filled document, then generate serially. Blank per-person cells stay blank. Shared narrative is explicitly labelled as applying to every row.
- Durable batch manifest before rendering and durable PDF record before advancing. Stop/background finishes saving an in-flight PDF without starting another. Restart requires explicit Resume. Storage/render errors leave unfinished work pending; a pending batch cannot silently be replaced.
- Separate state journals, up to 200 drafts and 500 PDF library entries, native PDF validation, A4 printing, sharing and Downloads export. Removing a library entry does not remove previously exported copies.
- Offline operation after the app is installed. No paid service, subscription or voice backend is required for these tools.

## Android rendering

`android/print/LekhpalDocumentRenderer.kt` waits for `onLayoutFinished` before `onWrite`, validates nonempty readable pages, atomically renames a temporary PDF, cleans up the renderer before resolving, and times out with recoverable progress. This avoids the intermittent empty-file result reproduced with the existing HTML-to-PDF dependency during repeated conversion. Other existing report generators retain their original behavior.

Native document export accepts only generated Lekhpal PDFs in the app's Documents directories. ERO's original private-directory export scope remains separate. An ERO failure-cleanup race was corrected so temporary cleanup finishes before its rejected Promise is reported.

- **14 native PDF file checks** and **12 native renders**: all six templates in both languages. Short fixtures fit on one A4 page; long inspection reports paginate. Rendered-page QA is under `outputs/qa/document-automation-2026-10-12/final-pdfs` and `final-contact-sheet.jpg`.
- Emulator-5556: Hindi editor and phone preview, PDF generation, two-person batch, background pause at 1/2, process restart, explicit Resume to 2/2, library search, Downloads, Android print preview and share chooser. No recipient or printer was selected.
- Extracted UI-batch PDFs contain the correct distinct names and plots; blank parent fields did not inherit the original person's name. Evidence: `ui-batch-checks.json` and phone screenshots in the same QA directory.
- Synthetic fixtures are test-APK assets generated by `node scripts/create-document-qa-fixtures.cjs`. They are not bundled into production. Test cleanup removes only those fixtures and verifies the UI-exported PDF bytes first, retaining other saved work.

## Limits

These are reviewable draft documents, not automatically issued orders, certificates or government submissions. Template coverage is these six workflows, not every state's prescribed form. Government acceptance and authenticated feeding remain separate tests. Community/voice backend work is unchanged.

A fresh process launch reached the dashboard and document tool successfully afterward. The document UI batch and restart recovery described above were exercised without debugger evaluation. This is recorded as a development-runtime observation, not represented as a diagnosed or permanently fixed engine issue.
